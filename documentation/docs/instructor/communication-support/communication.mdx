# Communication

Artemis enables students, tutors, and instructors to actively participate with its communication capabilities.
Various communication features allow students to engage with peers and ask all kinds of questions whereas moderators
(e.g., instructors and tutors) can provide general course information and answer content-related questions.
Communication can be made in different contexts, namely for lectures, exercises, or courses. Course participants can also
message each other to communicate in private. Below, you can find more information on specific features and how to use them.

## Enabling Communication

Artemis courses will by default enable all the communication features.
In case you do not want to provide users with these features, you can disable them on course creation by unchecking the
respective checkbox (`Communication Enabled`) - it can also be edited afterwards. Additionally, you can enable or disable group chats and direct messages by checking the (`Direct Messages Enabled / Group Chats`) checkbox.

## Features for Tutors

The following features are only available for tutors, not for students.

### Tutor Suggestions

*Suggestions provided by Iris to support tutors in formulating context-aware replies.*

Tutor Suggestions appear in the thread view whenever a tutor opens a discussion post. These suggestions are short, bullet-point messages generated by Iris based on the context of the current discussion, the course content, and linked lecture or exercise materials. Their purpose is to guide tutors toward pedagogically meaningful answers without providing direct solutions. Once Iris completes the analysis, the suggestions appear beneath the message input field. A status bar shows the loading state while the Tutor Suggestions are generated.

Exemplary thread view with tutor suggestions:

<Image src={tutorSuggestionsViewImg} alt={"tutor-suggestions-view"} size={ImageSize.medium} />

If tutors require more detailed clarification or want to refine the Tutor Suggestions, they can initiate a direct conversation with Iris in the integrated chat window. This chat appears directly below the suggestions in the thread view.
Tutors can ask questions such as:

* What part of the example solution relates to this question?
* What misconception might the student have based on their message?

Iris will respond based on available context, such as exercise content, example solutions, and previous messages. The tutor can use these answers to formulate more informed replies.

Example tutor–Iris conversation:

<Image src={irisChatViewImg} alt={"iris-chat-view"} size={ImageSize.medium} />

If the tutor's question leads to a refined understanding of the discussion, Iris may automatically regenerate and update the Tutor Suggestions. Additionally, tutors can trigger an automated regeneration.
A “View history” button lets them inspect previously generated suggestions.
Viewing previous suggestions:

<Image src={tutorSuggestionsHistoryImg} alt={"tutor-suggestions-history"} size={ImageSize.large} />

Tutor Suggestions are only available to users with the tutor role. The feature is disabled by default and must be explicitly enabled by the administrators. Students' messages are processed and stored locally within Artemis to generate suggestions. No external services are contacted, and no content is sent to GPT models.

    <li><strong>Opt-in</strong>: The feature is not active by default and must be explicitly enabled by the administrators.</li>
    <li><strong>No external AI</strong>: No content is sent to GPT models or other external AI services.</li>

### Autonomous Tutor

*Iris automatically drafts a response to a student question and posts it directly in the thread when it is confident enough, without requiring a tutor to act first.*

The Autonomous Tutor is triggered whenever a student posts a new message in a course communication channel. Iris analyzes the question, retrieves relevant course materials such as lecture slides, and searches the course's memory of previously tutor-verified answers. Based on this context, Iris generates a grounded response and evaluates how confident it is in its own answer. Unlike Tutor Suggestions, which only support a tutor while they compose a reply, the Autonomous Tutor can respond to the student directly.

Depending on the confidence score, one of three things happens:

* **High confidence**: Iris posts the response directly in the thread under the *Iris Bot* account, visible to all course members immediately.
* **Moderate confidence**: Iris drafts the response but does not post it to the student. It is held for tutor review and marked with an `Awaiting tutor review` badge, visible only to tutors.
* **Low confidence**: The response is discarded, and the question remains open for a tutor to answer manually.

Exemplary thread view with an autonomously posted response:

<Image src={autonomousTutorResponseImg} alt={"autonomous-tutor-response"} size={ImageSize.large} />

If a response requires tutor review, it appears in the thread with a yellow highlight and the `Awaiting tutor review` badge next to the Iris Bot sender name. Tutors can act on it directly from the thread using three buttons:

* **Approve** – accepts the response as-is and posts it to the student.
* **Edit** – lets the tutor correct the content before it is posted.
* **Reject** – discards the response entirely.

Reviewing an unverified response:

<Image src={autonomousTutorReviewImg} alt={"autonomous-tutor-review"} size={ImageSize.large} />

Once a tutor approves or edits a response, the badge disappears and the message becomes visible to the student, indistinguishable in structure from any other reply aside from the Iris icon and bot tag.

To help tutors keep track of pending reviews, a dedicated `Iris Review` tab in the tutor notification panel lists all unverified responses with a preview and timestamp.

The `Iris Review` notification tab:

<Image src={autonomousTutorNotificationTabImg} alt={"autonomous-tutor-notification-tab"} size={ImageSize.medium} />

In addition, the `Iris to verify` filter in the course's message overview collects every thread with a pending response, giving tutors a single place to work through them.

Threads awaiting verification in the message overview:

<Image src={autonomousTutorVerificationDashboardImg} alt={"autonomous-tutor-verification-dashboard"} size={ImageSize.medium} />

Every response that is approved or edited, as well as every thread that is marked as resolved, is distilled into a question-answer pair and stored in a persistent, course-scoped memory. Before generating a new response, Iris searches this memory for similar previously verified answers, so recurring questions receive consistent answers as the course progresses. Where possible, responses include a citation linking back to the source lecture slide or the earlier verified thread.

The Autonomous Tutor is only available in public course channels; private conversations are excluded. The feature is disabled by default and must be explicitly enabled by instructors in the course's Iris settings. All processing runs on self-hosted language models, and students who have opted out of AI interaction are excluded from every processing step, including reading, embedding, and storage.

<Callout variant={CalloutVariant.warning}>

  <strong>Privacy and activation at a glance</strong>

  <ul>
    <li><strong>Self-hosted inference</strong>: All response generation runs on self-hosted language models. No student data is sent to external providers or GPT models.</li>
    <li><strong>Opt-in</strong>: The feature is not active by default and must be explicitly enabled by instructors for the course.</li>
    <li><strong>Student opt-out</strong>: Students who have opted out of AI interaction are excluded from all processing steps, including reading, embedding, and storage of their messages.</li>
    <li><strong>Transparency</strong>: Every Iris-generated message carries the Iris icon and a bot tag. Responses awaiting tutor review remain hidden from students until a tutor approves or edits them.</li>
    <li><strong>GDPR</strong>: Processing is purpose-limited to assisting with student support (purpose limitation, data minimisation). If your institution requires consent as the legal basis, activation must be preceded by explicit <strong>consent</strong> (Art. 6(1)(a) GDPR).</li>
  </ul>
</Callout>

## Features for Moderators

The following features are only available for moderators, not for students.

### Pin Messages

By using the "Pin message" button, either from the right-click dropdown menu or from the action bar that appears at the top right corner
of a message when hovering over it, a moderator can *pin* the message. As a consequence, the message is highlighted to receive higher attention.

### Toggle Channel Privacy

Moderators have the ability to seamlessly toggle a channel’s privacy between private and public using
the toggle button in the channel settings.

## Features for Instructors

The following feature is only available for instructors that act as moderators.

### Creating Course-Wide Channels

When creating a lecture, exercise, or exam, the creator can decide on a channel name as well. The name is automatically generated based on the lecture's/exercise's/exam's title but can be adapted if needed.

The video below provides a demonstration for the creation of a course-wide channel:

<TumLiveVideo src="47623" title="Creating Course-Wide Channels" width={600} height={350} />

Besides automatic creation during lecture, exercise, or exam setup, moderators can also manually create new channels later
if needed. When creating a channel, they must choose between a *selective* channel (default option) and a *course-wide* channel.
In a *selective* channel, users are added manually after the channel is created. In a *course-wide* channel, all users
enrolled in the course are automatically added as members.

<Image src={channelCreationImg} alt={"channel-creation"} size={ImageSize.medium} />

### Message Announcements

Instructors can create course-wide messages that serve as *Announcements*.
They target every course participant and have higher relevance than normal messages.
Announcements can be created in the course messaging overview by selecting the `Announcement` channel.
As soon as the announcement is created, all participants who did not actively refrain from being notified will receive an email containing the announcement's content.
