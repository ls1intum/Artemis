This page is the complete reference for everything Artemis can hand out as a file: archives, repositories,
submissions, scores, and personal data. Each entry names the **minimum role** you need, where the action lives in the
user interface, and what you get back.

## Overview

The role column is the lowest role that may perform the action. A higher role can always do the same, and some entries
have extra conditions that are explained in their section.

## Archives

An archive is the complete record of a course or an exam, produced once and downloaded as often as needed.

### Archive a course

**Archive Course**, on the **Settings** page of the course in the course management, exports all course data. The
button appears only once the course end date has passed — while the course is still running there is nothing to
archive, so Artemis does not offer it.

<Image src={courseArchiveSection} alt="Course settings page with Archive Course in its title bar" size={ImageSize.large} caption="The archive section of the course settings page" />

For each exercise the archive contains the problem statement and a JSON file with the exercise details such as points.
For programming exercises, the template, solution, test and auxiliary repositories are included as well, and every
student repository is added as its own ZIP file inside the archive. All exams of the course are archived along with it.

Beyond the submissions, the archive carries the student data the course has accumulated: course and exam scores,
participation results with their feedback, posts and messages, competency progress, learner profiles, tutorial group
registrations, Iris chat sessions, and LLM token usage traces.

The archive is built asynchronously and you receive a notification once it is ready. **Download Archive**, on the same
page, hands it to you.

<Callout variant={CalloutVariant.warning}>

  Archiving compresses every repository and submission in the course and can run for hours on a large course, taking
  server resources with it. Start it when the instance is quiet.

</Callout>

For the exact list of what is and is not part of a course archive, see
[Course Archive](/admin/course-management#course-archive) in the administration documentation.

### Archive an exam

The same as a course archive, limited to a single exam, and likewise only possible once the exam end date has passed.
**Archive Exam** on the exam checklist page starts it, and **Download Archive** on that page hands it over.

<Image src={examArchiveChecklist} alt="Archive Exam on the exam checklist page" size={ImageSize.large} caption="Archiving from the exam checklist" />

## Programming exercise repositories

Every repository export is an ordinary ZIP file. Whether it carries the Git history differs per export and is stated
below, because that is what decides if the extracted folder is a usable repository or only a copy of the code.

<Callout variant={CalloutVariant.info}>

  Repositories that are exported with their history extract as a working Git repository: `git status` is clean and file
  permissions, including the executable bit on files such as `gradlew`, are preserved.

</Callout>

### Export programming exercise material

**Download Exercise**, on the exercise detail page, exports the material of a programming exercise: the template,
solution, test and auxiliary repositories, the problem statement, and the exercise configuration. This is the format
the exercise import reads, so it is the way to move an exercise to another course or another Artemis instance.

<Image src={exerciseExportButtons} alt="Export actions on a programming exercise detail page" size={ImageSize.large} caption="The export actions on a programming exercise" />

### Export student repositories in bulk

Exports the repositories of many participations at once, for graded and practice participations alike.

Open the **Scores** page of the exercise, click **Export**, and choose **Download Repos**. The same action is
available on the course exercises overview, where it exports the selected programming exercises together.

The **Export Repositories** dialog takes either a comma-separated list of logins or team short names, or
**Or download the repositories of all students**. Nothing is requested from the server until one of the two is set.

<Image src={repositoryExportDialog} alt="Repository export dialog with the participant selection and the rewrite options" size={ImageSize.large} caption="Choosing participants and export options" />

The dialog also offers options that rewrite what is exported:

| Option                                 | Effect                                                                              |
|----------------------------------------|-------------------------------------------------------------------------------------|
| **Add student name to project**        | Renames the project inside the repository so the participant is identifiable, and several can be imported into an IDE side by side. On by default |
| **Combine changes into one commit**    | Squashes the student commits into a single commit, which is easier to read than a history. On by default |
| **Normalize code style**               | Standardizes line endings and encoding                                                |
| **Filter late submissions**            | Moves the branch back to the last commit before **Date to filter late submissions**, which defaults to the due date |
| **Exclude practice submissions**       | Skips participations made after the due date in practice mode                         |
| **Anonymize repository**               | Removes the student name from the commit messages and the directory name              |

<Callout variant={CalloutVariant.info}>

  Tutors always receive anonymized repositories, so that assessment stays double-blind, and only an instructor may
  export every participation at once. Instructors can turn anonymization off.

</Callout>

Each participation appears in the archive as its own folder containing the code and a `.git` directory, so the full
history is available after extracting.

### Download a template, solution or test repository

**Download Repository** on the exercise detail page downloads one of the exercise's own repositories including its Git
history.

### Download an auxiliary repository

The same for an [auxiliary repository](/instructor/exercises/programming-exercise/create-an-exercise#auxiliary-repositories),
if the exercise defines any.

### Download a single student repository

**Download Repository** on a participation gives you that one repository as a ZIP file **without** the `.git`
directory, so it contains the submitted code but no history.

Students see this button on their own exercise page and can only download their own participation. Tutors and
instructors can download any participation from the scores page, the participations page, or the assessment view.

### Download the example solution

**Download Example Solution** gives you the solution repository as a ZIP file without the `.git` directory. Students
can do this only once the example solution publication date of the exercise has passed; before that, the button is
limited to tutors and above. **Download tests with example solution** appears in place of it when the exercise is
configured to release the tests together with the solution.

## Submissions, results and scores

The exercise **Scores** page collects the per-exercise exports behind one **Export** button. Which entries the
resulting **Export Options** list offers depends on the exercise type and on your role.

<Image src={scoresExportOptions} alt="Export Options list on the exercise scores page" size={ImageSize.large} caption="The export options of a text exercise" />

### Export exercise submissions

**Export Submissions** exports the submissions of everyone who participated in a text, modeling or file upload
exercise. Text submissions become text files, modeling submissions become JSON files, and file upload submissions are
exported as the uploaded files, each collected in one ZIP file. **Filter late submissions** cuts the export off at a
date you give, which defaults to the due date.

For programming exercises, use [Export student repositories in bulk](#export-student-repositories-in-bulk) instead.

### Export exercise results

**Export Results** exports the results of one exercise as a CSV file. For a programming exercise it offers three
levels of detail — **Without test cases**, **With test cases**, and **With test cases and feedback**, which adds a copy
of the feedback given for each failed test. Every other exercise type produces the plain file directly.

The file is assembled in your browser from the data already on the page, so it contains exactly the participations the
page shows.

### Export participant names

**Export Names** writes the participants of the exercise to a CSV file, without their results. Use it when you need
the list of who took part rather than how they did.

### Export course scores

The **Scores** page of the course management shows every student's points exercise by exercise, and **Export** turns
that table into a file.

<Image src={courseScoresExport} alt="Course scores page with the Export action in its title bar" size={ImageSize.large} caption="The course scores page" />

**Export** opens the **Export Options** dialog with a tab per format. **Excel** writes an `.xlsx` workbook and has
nothing to configure. **CSV** takes the three settings that decide whether another program reads the result correctly:
the **Field Separator**, whether strings are wrapped in **Quote Strings**, and the **Decimal Separator** — a comma for
locales that write `1,42`, a period for those that write `1.42`.

<Image src={exportOptionsDialog} alt="Export Options dialog with the Excel and CSV choices" size={ImageSize.large} caption="Choosing the file format and its separators" />

### Export exam scores

The same dialog, from the **Export** button on an exam's scores page.

### Export the exam student list

Exports the students registered for an exam as a CSV file, from the exam students page. Use it to hand the registration
list to another system, for example for seat planning.

## Other exports

### Export quiz questions

Exports the questions of a quiz, including their sample solutions, as a JSON file. **Export** on the detail page of the
quiz writes the whole quiz; the quiz question list of the course lets you pick individual questions across quizzes and
export only those.

The file is written by your browser from the quiz that is already loaded, and it can be imported into another quiz.

### Export tutorial groups

**Export Tutorial Groups** on the tutorial groups management page exports the groups with their registrations. The
dialog asks which fields to include and then writes them through **Export as CSV** or **Export as JSON**. See
[Tutorial groups](/instructor/communication-support/tutorial-groups).

### Export an exercise to the Sharing Platform

Publishes an exercise to a connected sharing platform instead of downloading it. This is only available when an
administrator has configured the platform. See [Sharing Platform](/instructor/integrations/sharing).

## User data

### Request your own data export

Exports everything Artemis stores about you: your account details, your submissions and results, the feedback you
received, your messages, and more. Follow **Privacy** in the page footer, then the **Data Export** link on the privacy
statement, and click **Request data export**. You confirm by typing your own login, and receive an email with a
download link once the export is ready.

<Image src={dataExportPage} alt="Data export page with the Request data export button" size={ImageSize.large} caption="Requesting your own data export" />

Programming exercise participations appear in the export as one folder per participation with a working `.git`
directory, so your own commit history is part of it.

You can hold one export at a time. Once you have downloaded it, or once Artemis has deleted it, the page names the date
from which you may request the next one.

The full list of what the export contains is documented on the student page,
[Exports](/student/tools-reference/exports).

### Request a data export for another user

Administrators can request and download a data export on behalf of a user, for example to answer a data access request
that reaches the institution rather than the platform. The action lives under Administration in the Data exports
section and produces the same archive as a self-service request.
