Artemis Intelligence is the set of AI-assisted capabilities implemented in Artemis and the integration contracts through which Artemis uses external EduTelligence services. This page identifies ownership and boundaries; the [developer AI pipeline catalog](/developer/ai-pipelines) records the Artemis control plane in more detail.

## Ownership and operational scope

The table deliberately separates **Artemis-native capabilities** from **external service integration contracts**:

- **Artemis-native:** Hyperion, Atlas agents/orchestration, and Artemis Global Search. Artemis owns their application-level workflows, authorization, and persisted Artemis data.
- **External services:** Iris/Pyris and Athena execute their own service pipelines. Artemis owns request construction, authenticated boundaries, callback handling, and client delivery where applicable.
- **Shared infrastructure:** A shared Weaviate instance does not merge Artemis Global Search with Iris RAG. Keep their collection namespaces separate when sharing an instance.

## Configuration versus implementation constraints

Feature flags and properties control whether Artemis loads or invokes these capabilities. They are not evidence of a particular deployment, model provider, endpoint, credential, capacity, or rollout state. For example, Hyperion and Atlas model access is configured through Artemis and Spring AI, while per-request AI-selection information can be forwarded at supported Iris boundaries.

Conversely, source-level implementation choices such as Artemis Global Search schemas, callback routes, job tracking, and feature gates are part of the integration contract. Consult the [developer AI pipeline catalog](/developer/ai-pipelines) before changing an Artemis-side boundary, and use the linked service documentation for service-owned implementation details.

## Lecture ingestion operations

Artemis keeps the queue and the state of lecture-unit ingestion; Iris runs the ingestion pipelines. A few operational rules apply when both sides are updated or tuned.

- **Update both together.** Artemis does not send jobs to Iris. The ingestion worker of Iris claims them from the Artemis queue. Update Iris and Artemis to compatible versions at about the same time. While Iris is on an older version or down, new jobs wait in the queue, and no work is lost. Runs that finish while Iris is still on an older version are confirmed without a fingerprint in the index; reconciliation detects this through the Iris census and ingests those units again.
- **Ingestion worker.** Iris must reach the Artemis server URL, and its `ingestion_worker.enabled` setting must stay on (the default). Iris learns the Artemis URL from the health checks that Artemis sends it.
- **Which courses are ingested.** Global search uses the ingested lecture content of every course, so ingestion does not depend on the course's Iris setting. That setting only switches off the Iris chat and the other interactive Iris features, including the Iris answer in global search, which uses only courses with Iris on. New uploads and edits are always ingested. The backfill and the reconciliation walk catch up on older content only for courses that are still running or ended within `artemis.iris.ingestion.course-window` (default `P730D`, two years). They start with the newest courses (running courses first, then by end date) and work backwards. For older courses, the walk only removes index rows of deleted units. FAQ ingestion still follows the course's Iris setting.
- **FAQ reconciliation.** Artemis synchronizes accepted FAQs asynchronously when they are created or edited, and only for courses with Iris enabled. FAQ deletion also runs asynchronously. These operations use the `default` FAQ ingestion variant independently of the course's chat variant. An Iris outage does not prevent saving or deleting FAQs. If the bounded synchronization queue is full, the immediate attempt is skipped and reconciliation recovers it. Every 10 minutes (`artemis.scheduling.faq-ingestion-reconcile-time`), the scheduling node compares the Iris FAQ census of this instance with the accepted FAQs of every course with Iris enabled. It sends FAQs that are missing, changed or stored twice. It deletes only FAQs that this instance stored in Iris for a course with Iris enabled and that no longer exist or are no longer accepted. FAQs of courses with Iris disabled, and older FAQ entries that do not name their Artemis instance, are left as they are. One run sends or deletes at most `artemis.iris.faq-reconcile.max-actions-per-run` FAQs (default 20). This also refills the FAQs after the vector store was replaced. When the census is unavailable (an older Iris without the census endpoint, an error, or a timeout), the run sends and deletes nothing.
- **Reconciliation.** `artemis.scheduling.lecture-ingestion-reconcile-time` starts a walk over all courses that compares the Iris census with the Artemis state (default every 15 minutes). Set it to `-` to disable the walk. While a walk is active, it takes its next step every `artemis.iris.ingestion.reconcile.continuation-interval` (default 30 seconds). `artemis.iris.ingestion.reconcile.max-backlog` (default 3) limits how many units the walk and the backfill keep open at the same time: queued, running, or with a retry that is due. A failed unit that waits for its retry time does not count, so a unit that keeps failing for its own reasons does not stop other work. The walk therefore adds units only as fast as Iris finishes them. When at least `max-backlog` units failed within `artemis.iris.ingestion.reconcile.outage-pause-window` (default 30 minutes) and no unit was ingested successfully in that time, the walk and the backfill pause, because Iris is probably down. Failures caused by the unit itself, such as an unreadable file or a video that cannot be loaded, do not count. `artemis.iris.ingestion.census-timeout` (default 60 seconds) bounds one census request.
- **Video links.** Iris transcribes YouTube videos, and TUM Live videos when `artemis.tum-live.api-base-url` is set. A unit whose only content is a link to another video page is marked as not processed. When TUM Live cannot resolve a TUM Live link (the course is not public, the recording is not uploaded yet, or TUM Live is down), Iris ingests the PDF and any stored transcript without the video. The walk tries the video again every `artemis.iris.ingestion.reconcile.video-pending-recheck` (default 6 hours). A unit with no other content than such a video fails and is retried later.
- **Lost runs.** A run lost to an Iris restart, a lapsed worker lease, or an abandoned claim is queued again without using its retry budget. After `artemis.iris.ingestion.max-unsettled-attempts` (default 3) such attempts in a row, the next attempt counts as a failure, so the normal retry limit stops a unit that keeps losing its runs.

## Atlas model configuration

The LLM-backed part of Atlas is off by default and is turned on with `artemis.atlas.atlasllm.enabled`. It covers the course chat agent, autonomous competency orchestration, the tool surfaces they call, and the Responses adapter, and it needs LLM presets assigned under `artemis.atlas.atlasllm.llm-presets`. Leaving it off keeps competencies, learning paths, and learner profiles available and loads none of those beans, so an installation without an LLM starts faster and runs neither the content-change scheduler nor the autonomous exercise event listener.

Before upgrading from a release with AtlasML, remove `artemis.atlas.orchestrator.max-atlasml-calls-per-run` from deployment configuration. The orchestrator rejects unknown properties, so retaining this removed setting prevents startup. The removed `artemis.atlas.atlasml.*` settings are ignored and can also be deleted.

Set the flag in the configuration directory the server reads at startup, or as the environment variable `ARTEMIS_ATLAS_ATLASLLM_ENABLED`. Setting it in a copy of `application-artemis.yml` inside the deployed artifact has no effect, because the `core` profile is activated after `artemis` and the value in `application-core.yml` wins.

Atlas reads its models from the presets under `artemis.llm`, described in [LLM configuration](./llm-configuration).
It has four tasks: `chat` (the AI Competency Assistant), `orchestrator` (autonomous competency orchestration),
`worker` (the stateless Creator, Assigner, and Editor workers) and `flavor-strip` (removing narrative text from
exercises before extraction). A task without its own key uses `default`:

```yaml
artemis:
    atlas:
        atlasllm:
            enabled: true
            llm-presets:
                default: small
                orchestrator: large
                chat: atlaschat
```

The preset's `api` decides whether a task uses the Responses API or Chat Completions; there is no separate switch.
Orchestration and its workers replay encrypted reasoning with `store: false`, so their presets need a provider or
gateway that supports `/responses` with function tools, or `api: chat-completions`. No automatic transport fallback
occurs after an error. If flavor stripping fails, Artemis keeps the original text.

Each autonomous run has a fixed tool-call budget. A run that exhausts it, or ends without a verified result, ends as failed if it changed nothing and as partial otherwise, and Artemis does not retry it automatically. The [developer AI pipeline catalog](/developer/ai-pipelines#atlas-agents-and-competency-orchestration) lists the exact limits.

## Atlas agent

### Enable the Atlas agent

The Atlas agent consists of the **AI Competency Assistant**, a chat in which instructors build competencies, relations, and exercise links and approve every change, and automatic competency updates, which change competencies and their exercise and lecture-unit links without prior approval. The [instructor documentation](/instructor/analytics/atlas-agent) describes both from the course perspective. Several switches have to be on, in this order:

| Switch                               | Where                                                            | What it unlocks                                                                                                                                                                                               |
| ------------------------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `artemis.atlas.enabled`              | Server configuration                                             | Competencies, learning paths, and the **Atlas (Adaptive Learning)** module.                                                                                                                                   |
| `artemis.atlas.atlasllm.enabled`     | Server configuration (see above for the `core` profile)          | Loads the chat and the automatic updates. Without it, none of the Atlas LLM code runs. Shown as **Atlas AI (LLM)** on the **Features** screen.                                                                |
| **Atlas Agent**                      | Runtime toggle on the **Features** screen, off by default        | Shows the AI Competency Assistant and **Suggest competencies** to instructors, and allows automatic updates.                                                                                                  |
| **Atlas Auto-Orchestration Enabled** | Course edit form, visible only to administrators, off by default | Automatic competency updates for this course. **Debounce Window Override (seconds)** and **Daily Run Limit Override** change the defaults for this course. Turning it off discards the changes still waiting. |
| `scheduling` profile                 | At least one server node                                         | Starts automatic runs. Manual **Suggest competencies** runs do not need it.                                                                                                                                   |

Turning off the **Atlas Agent** toggle hides the chat in the client and blocks **Suggest competencies** and automatic updates on the server, but the chat endpoint itself is not guarded by the toggle. To stop all Atlas calls to the language model, turn off `artemis.atlas.atlasllm.enabled`. Turning anything off never changes existing competencies, although a run that is already in progress still finishes.

Atlas sends course content to the configured model: problem statements, example solutions, quiz questions with their correct answers, lecture-unit text, and, for the chat, the course description and the instructor's messages. It sends no student submissions or other personal student data. The [instructor documentation](/instructor/analytics/atlas-agent#what-atlas-sends-to-the-language-model) lists the data in detail.

### Chat and scheduling settings

| Property                                              | Default        | Meaning                                                                                    |
| ----------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------ |
| `artemis.atlas.orchestrator.debounce-window-seconds`  | `1800`         | How long a course's content must stay unchanged before an automatic run starts.            |
| `artemis.atlas.orchestrator.max-daily-orchestrations` | `10`           | Automatic runs per course and day. The count resets at midnight in the server's time zone. |

The presets of the chat and of automatic updates are assigned as shown in the YAML example above. Administrators can override the two scheduling values per course in the course edit form.

### Costs and notifications

The defaults limit automatic runs, but they are no hard cost ceiling. **Suggest competencies** runs ignore the waiting time and the daily limit and do not count towards it, and the per-course **Daily Run Limit Override** has no upper bound. Artemis records the token usage of automatic updates and flavor stripping, which appears in [token usage tracking](/admin/hyperion#token-usage-tracking) with a USD amount when the provider reports it or the endpoint has a [price list](./llm-configuration#costs). The chat conversation of the AI Competency Assistant is not recorded.

After each automatic run that changed something, stopped halfway, or failed, Artemis sends an email listing the changes (up to 50) to the instructors of the course and to all active administrators. Every recipient can turn it off per course in the course notification settings, under **Automatic competency updates (instructors)**; there is no instance-wide switch.

### Troubleshooting

| Symptom                                                                  | Cause and fix                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Atlas AI (LLM)** stays inactive although it is enabled                 | The value was set in a packaged `application-artemis.yml`, which `application-core.yml` overrides. Set it in the external configuration or as `ARTEMIS_ATLAS_ATLASLLM_ENABLED`.                                                     |
| The server does not start and lists `artemis.atlas.atlasllm.llm-presets` keys | `artemis.atlas.atlasllm.enabled` is on, but a task has no preset. Set `default` or the listed keys, see [LLM configuration](./llm-configuration).                                                                                   |
| Automatic runs never start in any course                                 | No server node runs the `scheduling` profile.                                                                                                                                                                                       |
| Instructors do not see the chat button                                   | The **Atlas Agent** toggle or **Atlas AI (LLM)** is off, or the user is not an instructor of the course.                                                                                                                            |
