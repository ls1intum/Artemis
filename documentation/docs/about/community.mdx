# Community

Artemis is developed in public. Design discussions, reviews, and decisions happen on GitHub, so the
project's history is readable without joining anything. The channels below are the ones that actually
exist today.

## Where to go

| I want to | Use |
| --- | --- |
| Ask a question about using or operating Artemis | [GitHub Discussions, Q&A category](https://github.com/ls1intum/Artemis/discussions/categories/q-a) |
| Report a bug | [Open a bug report](https://github.com/ls1intum/Artemis/issues/new/choose) |
| Propose a feature | [Open a feature request](https://github.com/ls1intum/Artemis/issues/new/choose) |
| Report a security vulnerability | Privately, following the [security policy](https://github.com/ls1intum/Artemis/blob/develop/SECURITY.md). Not as a public issue. |
| Contribute code or documentation | [CONTRIBUTING.md](https://github.com/ls1intum/Artemis/blob/develop/CONTRIBUTING.md) and the [development process](/developer/development-process) |
| Follow releases | [GitHub releases](https://github.com/ls1intum/Artemis/releases) |
| See what is being built | [Roadmap](./roadmap) |
| Try Artemis without setting anything up | [Try Artemis](./try) |
| Understand who decides what | [Project governance](./governance) |
| Reach the team about your institution | [artemis@xcit.tum.de](mailto:artemis@xcit.tum.de) |

<Callout variant={CalloutVariant.info}>
    Please do not file questions or support requests as issues. The Q&A category in GitHub Discussions
    exists for them, and answers there stay findable for the next person with the same question.
</Callout>

## Contacting the team directly

Some things do not belong in a public issue. Write to
[artemis@xcit.tum.de](mailto:artemis@xcit.tum.de) for:

- a Slack invitation (see below),
- a backport of a fix to an older release, or support on a release you cannot upgrade away from,
- hosting an instance for a school or for a trial,
- adding your institution to the [adoption page](./adoption),
- anything else that concerns your institution rather than the project as a whole.

## Day-to-day development

Coordination between contributors during a review also happens on Slack. Access is not self-service
today: request an invitation at [artemis@xcit.tum.de](mailto:artemis@xcit.tum.de). Everything that
affects a decision is expected to end up in the issue or pull request, so following the repository is
enough to stay informed.

The maintainers meet weekly, and that meeting is where disagreements that a pull request thread has not
settled are resolved. See [project governance](./governance#weekly-maintainer-meeting).

## Ground rules

All community spaces are governed by the
[Code of Conduct](https://github.com/ls1intum/Artemis/blob/develop/CODE_OF_CONDUCT.md). Contributions
additionally follow the identity and transparency policy in
[CONTRIBUTING.md](https://github.com/ls1intum/Artemis/blob/develop/CONTRIBUTING.md): contributors use
their real name and an authentic profile picture, which is what makes review and accountability work in
a project used for examinations.
