For local Artemis development, we recommend [LM Studio 0.4.29](https://lmstudio.ai/changelog/lmstudio/lmstudio-v0.4.29)
with [Qwen/Qwen3.8-27B](https://lmstudio.ai/models/qwen/qwen3.8-27b). This setup lets you test Hyperion locally without cloud API keys.

<Callout variant={CalloutVariant.info}>
    For production setups with cloud providers (OpenAI, Microsoft Foundry), refer to [LLM configuration](/admin/llm-configuration).
</Callout>

## Prerequisites

- A running Artemis instance with the `local` profile
- Sufficient disk space for downloading LLM models (typically 10-40GB per model)

## Setting up LM Studio

### Install LM Studio

Install LM Studio using Homebrew:

```bash
brew install --cask lm-studio
```

### Download and Configure a Model

#### Configure LM Studio via the GUI

1. Open **Model Search** in LM Studio and search for `qwen/qwen3.8-27b`.
2. Download a quantization that fits your hardware and load the model.
3. Open **Developer** and start the local server.

The GUI application enables you to see logs and interact with the model in a chat similar to ChatGPT.

#### Configure LM Studio via CLI

LM Studio provides a CLI tool (`lms`) for managing models and the server. For more information, see the [LM Studio CLI documentation](https://lmstudio.ai/docs/cli).

1. Download a model

    ```bash
    lms get qwen/qwen3.8-27b
    ```
2. Load the model to activate it

    ```bash
    lms load qwen/qwen3.8-27b --context-length 32000
    ```

3. Start the LMS server

    ```bash
    lms server start
    ```

The LLM service should now be running on http://localhost:1234.

#### Verify the Service Works

Send a prompt to the same endpoint Artemis uses and check that the response contains a reply in `output`.

```bash
curl --fail-with-body http://localhost:1234/v1/responses \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen/qwen3.8-27b","input":"Reply with hello.","store":false}'
```

If you loaded the model under a custom identifier, use its `id` from `GET /v1/models` in both the request and the Artemis preset.

## Configuring Artemis

Add the following configuration to your `application-local.yml` file (or adapt your existing configuration accordingly):

```yaml
artemis:
  llm:
    endpoints:
      lmstudio:
        # Artemis appends /responses itself, so the base URL includes the /v1 prefix.
        # Without api-key Artemis sends no Authorization header, which LM Studio does not need.
        base-url: http://localhost:1234/v1
    presets:
      local:
        endpoint: lmstudio
        model: qwen/qwen3.8-27b
        api: responses
        temperature: 0.7
  hyperion:
    enabled: true
    llm-presets:
      default: local
```

    For production setups with cloud providers (OpenAI, Microsoft Foundry), refer to [LLM configuration](/admin/llm-configuration).
</Callout>

## Testing the Integration

1. Start the Artemis server _(Make sure the Artemis Server Run Configuration includes the `local` profile)_
2. Start the Artemis client
3. Create a programming exercise and open it via the **Edit in Editor** button
4. Click the **Check Consistency** button
5. At startup, the **Artemis Server logs** list each assignment, for example:
    ```
    LLM artemis.hyperion.llm-presets.consistency-check -> local (default) | qwen/qwen3.8-27b | responses | localhost | timeout PT5M, retries 3, auth none, no fallback price
    ```
6. View the **LMS Server logs**
    1. Via CLI
        ```bash
        lms log stream
        ```
    2. By opening LM Studio GUI and activating the Developer view
7. Verify the logs
    1. include the prompt sent from Artemis
    2. show progress status
    3. show the generated prediction

When a feature expects JSON, ask Qwen to return only the JSON object and parse the result with the feature’s output converter.
In local testing, LM Studio 0.4.29 accepted a Responses request with a JSON schema in `text.format`, but Qwen sometimes wrapped its answer in Markdown code fences.

## Performance Considerations

- **Model Size**: For Qwen3.8-27B, a lower-bit quantization uses less memory. Leave enough memory for the context window and the local Artemis instance.
- **Context Length**: The `--context-length 32000` parameter controls how much text the model can process at once. Adjust based on your hardware capabilities.
- **GPU Acceleration**: LM Studio automatically uses GPU acceleration when available (Metal on macOS, CUDA on Linux/Windows).

## 🛠 Troubleshooting

### Exit Code 6 When Loading a Model

If you encounter the following error:

```
🥲 Failed to load the model
Error loading model. (Exit code: 6)
```

This usually means the model cannot load because the required runtime engine is missing or broken.

#### ✅ Fix: Repair the MLX Runtime (macOS Apple Silicon)

1. Open **LM Studio**
2. In the left menu, click **LM Runtimes**
3. Under **Runtime Extension Packs**, find:

   **LM Studio MLX**

   (Engine used for MLX / Apple Silicon models)

4. If LM Studio detects an issue, a **Fix** button will appear
5. Click **Fix** to reinstall, update, or repair the engine

After the repair completes, try loading your model again.
