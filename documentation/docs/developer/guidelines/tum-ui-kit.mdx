# TUM UI package

`@tumaet/ui-angular` is a private Angular package in `packages/tum-ui`. Artemis production builds
consume its compiled public entry point and stylesheet instead of application-internal sources.

<Callout variant={CalloutVariant.warning}>
    New Artemis UI uses PrimeNG. This package is an extraction boundary for existing TUM UI code, not a second Artemis component standard. Do not duplicate a native HTML, PrimeNG,
    Angular CDK, or Angular Aria control to expand the package.
</Callout>

## Ownership boundary

Package code:

- imports only its declared dependencies;
- exposes supported contracts through `src/public-api.ts`;
- uses package-owned translation keys and semantic `--tum-ui-*` theme variables;
- contains no Artemis routes, services, translation keys, theme variables, or request models.

Artemis-specific adapters live in `src/main/webapp/app/shared-ui/tum-ui-integration`. Artemis
imports package symbols from `@tumaet/ui-angular`; deep imports and imports from the former
in-application path are rejected by ESLint.

The package is private. Removing `private: true` requires release ownership, a versioning policy,
and compatibility testing against supported consumers.

## Adding or changing a component

Before writing code:

1. For Artemis-only UI, use the PrimeNG component selected by
   [Client Development](/developer/guidelines/client-development).
2. For package work, confirm that a reusable TUM UI contract is required and that an existing
   native, CDK, or Angular Aria primitive cannot supply the behavior.
3. Keep host policy outside the package. Add an adapter in Artemis when integration requires
   application translations, request types, routing, or theme values.

Package components use standalone declarations, signal APIs, `ChangeDetectionStrategy.OnPush`, and
semantic Tailwind utilities. Prefer native controls and CDK or Angular Aria behavior over custom
keyboard, focus, overlay, or selection machinery.

Tests should assert public behavior: accessible role and name, keyboard interaction, focus changes,
disabled behavior, emitted values, and forms integration. Avoid tests that restate implementation
details or static class maps.

### Stories

Colocate each top-level consumer story with its component or directive. Document supporting pieces
of a composite API, such as tab panels or sortable columns, as subcomponents of that story. Use the
package's [stable CSF3 format](https://storybook.js.org/docs/api/csf) with `Meta`, `StoryObj`, and
TypeScript's `satisfies` operator. Keep configuration in `packages/tum-ui/.storybook`; do not add
root Storybook configuration or import Artemis into a story.

Prefer an args-driven default story and only the additional states that expose a meaningful visual
or behavioral contract. Add a `play` function for browser-only behavior such as focus, keyboard
navigation, overlays, or dismissal. Query by accessible role and name. Do not assert CSS classes,
duplicate unit-test matrices, add snapshots, or disable accessibility rules to make a story pass.

The [Angular Vite framework](https://storybook.js.org/docs/get-started/frameworks/angular-vite) is
a preview integration. Verify HMR, browser tests, and the static build before upgrading it.

## Consuming the package

Import only from the package root:

```ts
import { TumUiButtonComponent, TumUiDialogComponent } from '@tumaet/ui-angular';
```

The TypeScript declarations at that entry point are the component API reference. Do not duplicate
input and output tables in documentation; they drift from the compiled contract.

Artemis declares the package through pnpm's `workspace:*` protocol. Non-serve application builds map
`@tumaet/ui-angular` to `packages/tum-ui/dist`, while Vitest aliases the package
source so a focused test works on a cold checkout; the production build and package checks continue
to validate the compiled ng-packagr boundary.

### Theme contract

The [package README](https://github.com/ls1intum/Artemis/blob/develop/packages/tum-ui/README.md) is
the source of truth for stylesheet loading, token semantics, dark mode, and `styleClass`.

The style build emits the ignored package-root `styles.css`; ng-packagr copies that asset into the
compiled package. Artemis loads `@tumaet/ui-angular/styles.css` after its framework styles and maps
package tokens to PrimeNG and Artemis tokens in `src/main/webapp/tailwind.css`. Package styles must
not read Artemis or PrimeNG variables directly. Artemis sets `data-theme="dark"` on the document
element when dark mode is active.

### Translation contract

Package-owned text uses `tumUi.*` keys and has English defaults. A host can implement
`TumUiTranslator` and register it once:

```ts
providers: [provideTumUiTranslator(ApplicationTranslator)];
```

The adapter's `changes` signal invalidates translated views, and its `locale` signal controls
locale-sensitive formatting. Artemis registers `provideArtemisTumUiTranslator()` in
`app.config.ts`; its key mapping belongs in `app/shared-ui/tum-ui-integration`, not in the package.

## Local workflow

From the repository root:

| Command                                              | Purpose                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------- |
| `pnpm run tum-ui:build`                              | Build the production Angular package in `packages/tum-ui/dist`            |
| `pnpm run tum-ui:build:watch`                        | Watch package sources and its precompiled stylesheet                      |
| `pnpm run tum-ui:test`                               | Run package Vitest specs                                                  |
| `pnpm run tum-ui:test:coverage`                      | Run package specs with the CI coverage thresholds                         |
| `pnpm run tum-ui:stylelint`                          | Check package CSS and SCSS                                                |
| `pnpm run tum-ui:pack:check`                         | Build and validate an isolated artifact with publint and AreTheTypesWrong |
| `pnpm --dir packages/tum-ui run storybook`           | Build package styles and start its isolated Storybook                     |
| `pnpm --dir packages/tum-ui run storybook:typecheck` | Type-check Storybook configuration and stories                            |
| `pnpm --dir packages/tum-ui run storybook:test`      | Run stories and accessibility checks in Chromium                          |
| `pnpm --dir packages/tum-ui run storybook:build`     | Build the static package Storybook                                        |
| `pnpm --dir packages/tum-ui run storybook:docs:test` | Build Storybook and test AutoDocs themes and responsive viewports         |

`pnpm start` and the shared IntelliJ client configuration generate the package stylesheet and serve
Artemis through the same command. Serve mode resolves the public entry point from source and polls
workspace files because native Angular watching does not report package changes reliably. Generated
styles are staged after component changes so Angular can hot-update the template and global
stylesheet separately. This adds up to one polling interval to package updates, while every
non-serve build continues to compile and consume `packages/tum-ui/dist`. Restart the client after
changing the package manifest or build configuration. Package validation writes to
`packages/tum-ui/dist-pack`, so it cannot replace the artifact used by other commands.

Before submitting a package change, run:

```bash
pnpm run tum-ui:test:coverage
pnpm run lint
pnpm run tum-ui:stylelint
pnpm run tum-ui:pack:check
pnpm run test:rules
pnpm run compile:tests
pnpm --dir packages/tum-ui run storybook:typecheck
pnpm --dir packages/tum-ui run storybook:test
pnpm --dir packages/tum-ui run storybook:docs:test
```

`pnpm run test:rules` checks the package manifest against the canonical versions in
`pnpm-workspace.yaml` and verifies the development and production package configurations remain
equivalent apart from incremental-output cleanup.

## Review checklist

- The need belongs in this package rather than PrimeNG or Artemis application code.
- Public imports resolve through `@tumaet/ui-angular`.
- The public API contains only supported symbols.
- Interaction behavior delegates to native HTML, CDK, or Angular Aria where available.
- Accessible names, keyboard behavior, focus, and forms integration have behavioral tests.
- Styling uses semantic package tokens and works with host-provided light and dark values.
- Stories cover representative states; unique browser behavior is tested through accessible queries.
- Package text has an English default; host translations stay in the adapter.
- Dependency changes update the appropriate workspace catalog and package manifest together.
- The packed artifact passes `tum-ui:pack:check`.
